PROBLEM
──────────────────────────────────────────────────────────────────────────────
CEL expressions → 9-20MB per policy → unbounded cache → OOM at ~500 policies


SOLUTION
──────────────────────────────────────────────────────────────────────────────
LRU cache with 512MB limit + automatic eviction → memory capped forever

CACHE METRICS (Available)
──────────────────────────────────────────────────────────────────────────────
cache.GetMetrics() returns:
  • Hits              - Number of cache hits
  • Misses            - Number of cache misses
  • Evictions         - Number of LRU evictions
  • CurrentSize       - Current cache size in bytes
  • CurrentCount      - Number of policies in cache
  • MaxSize           - Maximum cache size (512MB)

cache.HitRate() returns:
  • (hits) / (hits + misses) → typically 95%+


THREAD SAFETY
──────────────────────────────────────────────────────────────────────────────

✓ Safe for concurrent requests


LRU EVICTION LOGIC
──────────────────────────────────────────────────────────────────────────────
When new policy needs to be cached:
  IF cache_size + new_policy_size > 512MB:
    WHILE cache too full:
      Evict least-recently-used policy from back of list
    Add new policy to front
  ELSE:
    Add new policy to front (no eviction needed)

"Recently used" = last accessed (any Get or Put operation)

COMMON QUESTIONS
──────────────────────────────────────────────────────────────────────────────
Q: What happens when cache is full?
A: Least-recently-used policies are evicted automatically

Q: Will policies need to be recompiled after eviction?
A: Yes, but rarely happens (95%+ hit rate means 5% of requests trigger recompile)

Q: Is there any latency impact?
A: No - cache operations are O(1), same as original map

Q: What if 512MB is not enough?
A: Can configure higher limit (1GB, 2GB, etc.)

Q: Does eviction lose data?
A: No - policies are still in etcd, can be recompiled if needed

Q: Can I monitor cache behavior?
A: Yes - GetMetrics() provides hits, misses, evictions

Q: Is this backwards compatible?
A: Yes - can be enabled/disabled without code changes
